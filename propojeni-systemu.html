Kudy tečou data — číslované spoje
  1. Zákazník → Web — návštěva webu, vyplnění poptávkového formuláře.
  2. Web ⇄ Site runtime — živý obsah z content hubu + náhledy draftů (obousměrně).
  3. Web → API — odeslání formuláře na POST /site/v1/forms/{formKey}/submit → vznikne submission + lead ve workspace (viditelné v portálu); zpět: publish (verze webu).
  4. API ⇄ Runtime — content / verze / runtime-config a preview tokeny.
  5. API ⇄ Supabase — veškerá data (schema platform_v1), auth přes GoTrue, media ve Storage.
  6. TURBOW → API — po WON leadu: HMAC-podepsaný handoff na /internal/v1/provisioning/handoffs → workspace + objednávka + entitlementy + pozvánka do portálu.
  7. TURBOW → Web — generace webu (manifest + site-bundle, stav COMPATIBLE) a následný connect → CONNECTED (import obsahu do hubu).
  8. Portál ⇄ API — vše přes JWT: bootstrap, obsah, formuláře, poptávky, publikace, AI správa webu.

Kdo co dělá — role systémů

TURBOW (lokální)

  • Sbírá poptávky z marketingových webů (leady) a vede prodejní pipeline.
  • Po WON vytvoří handoff job → CP API (nikdy neblokuje prodej při výpadku CP).
  • Generuje weby (audit → brief → generace → validace COMPATIBLE).
  • Registr zdrojů (webybudoucnosti/webyprobyznys): barvy, e-mail, portál — brand odpovědí.
  • Ukládá si jen reference: platform_workspace_id, platform_website_id.

Customer Platform API (Vercel)

  • Jediný zdroj pravdy — veškerá logika na serveru, portál je jen UI.
  • Workspaces + členové + role (owner/admin/editor/sales/viewer), tenant izolace.
  • Obsah → draft / publish / verze / restore; dopad změn na weby.
  • Formuláře (definice + submissions), leady se stage, nabídky z leadu.
  • AI správa obsahu: propose → change set → publish / rollback (SDK i portál).
  • Provisioning handoffů (S2S, HMAC, idempotentní) + pozvánky uživatelů.

Supabase

  • Postgres platform_v1 — 69 tabulek: workspaces, weby, obsah, formuláře, leads, nabídky, objednávky, provisioning…
  • GoTrue — login e-mailem a heslem, JWT (JWKS verifikace), session refresh.
  • Storage pro media (fotky/loga webů).
  • RLS + nulové policy = default deny; přístup jen přes service role na serveru.

Web zákazníka

  • Stav COMPATIBLE: manifest.json + site-bundle.json, běží standalone, formulář = mailto, demo badge.
  • Stav CONNECTED: má Website ID + secrets v env, formuláře jdou do API, obsah z hubu, badge zmizí.
  • Žádná data neukládá lokálně — vše ve workspace.

Portál zákazníka

  • Login, dashboard s onboardingem, /weby, /obsah, /formulare, /poptavky, /nabidky, /media, /automatizace, /statistiky, /nastaveni.
  • Účet vzniká pozvanou (invite e-mail — vyžaduje SMTP) nebo adminem.
  • Branding dnes „Webdo24 Portál“; multi-značkové domény = návrh (registry zdrojů).
